A client could reach its local gateway and an internal application server but could not reach the public destination. Investigation focused on routing, NAT configuration, NAT classification, translation state, and packet behavior.

Root Cause

The NAT overload configuration on R1 was correctly configured to translate traffic from the inside interface out through GigabitEthernet0/2. However, the standard NAT-INSIDE access list referenced the wrong source network.

Broken NAT ACL

ip access-list standard NAT-INSIDE
 permit 10.10.20.0 0.0.0.3

The client-facing LAN was configured as 10.10.10.0/24, so client traffic from that network did not match the NAT-INSIDE ACL. As a result, R1 did not create the required NAT translation entries for the affected traffic.

Corrected NAT ACL

ip access-list standard NAT-INSIDE
 permit 10.10.10.0 0.0.0.255

The ACL was corrected to match the actual inside LAN. After the change, the ACL began matching client traffic and NAT translations were created successfully.

This conclusion was supported by the configuration comparison, empty pre-remediation NAT translations, packet capture analysis, post-remediation ACL match counters, populated NAT translations, and successful public connectivity.

Remediation

The NAT-INSIDE ACL was corrected from the incorrect 10.10.20.0/30 source network to the actual client LAN, 10.10.10.0/24. 

no ip access-list standard NAT-INSIDE

ip access-list standard NAT-INSIDE
 permit 10.10.10.0 0.0.0.255

Existing NAT translations were then cleared and the configuration was saved so subsequent client traffic would be evaluated against the corrected NAT policy. 

clear ip nat translation *
write memory

Investigation Methodology

The incident followed a structured network troubleshooting workflow:

  1. Confirm the client symptom.
  2. Verify local gateway connectivity.
  3. Verify internal application connectivity.
  4. Test the public destination.
  5. Verify interface state and addressing.
  6. Verify routing.
  7. Inspect NAT configuration and NAT ACL behavior.
  8. Inspect NAT translation and statistics.
  9. Correlate packet captures with router state.
  10. Apply the NAT correction.
  11. Verify translation entries and statistics.
  12. Validate public connectivity and traceroute.
  13. Confirm the working packet flow in Wireshark.
  14. Document and close the incident.
