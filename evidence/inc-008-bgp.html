INC-009 — HSRP CLI Evidence

Cisco IOS HSRP commands were used to verify the Active and Standby gateway roles, compare the HSRP virtual IP configuration between R1 and R2, investigate the failover condition, and verify the corrected virtual gateway after remediation.

HSRP Configuration

R1 — show running-config interface

show running-config interface GigabitEthernet0/0

Used to inspect R1's LAN interface and verify the configured HSRP virtual IP, priority, and preemption.

HSRP State

R1 — show standby brief

show standby brief

Used to verify R1's HSRP group, priority, Active state, and virtual IP.

HSRP Detail

R1 — show standby

show standby

Used to inspect detailed HSRP state, virtual IP, Active router, priority, and HSRPv2 operation.

Broken Configuration

R2 — show running-config interface

show running-config interface GigabitEthernet0/0

Used to compare R2's HSRP configuration with R1 and identify the mismatched virtual IP.

R2 was configured with 10.10.10.11 instead of the expected HSRP virtual IP 10.10.10.1.

HSRP State

R2 — show standby brief

show standby brief

Used to verify R2's HSRP role and compare its virtual IP with the client-facing gateway.

HSRP Detail

R2 — show standby

show standby

Used to inspect the detailed HSRP state and confirm the incorrect virtual IP before failover testing.

Failover Testing

R2 — show standby after R1 failure

show standby

Used after R1 failed to verify whether R2 transitioned to the Active state and whether it was providing the expected virtual gateway.

R2 transitioned to Active, but the virtual IP remained 10.10.10.11. The expected client gateway was 10.10.10.1.

Failover Verification

R2 — show standby brief after R1 failure

show standby brief

Used to confirm the Active state after the simulated primary-router failure.

Post-Remediation

R2 — show standby with corrected VIP

show standby

Used after remediation to verify that R2 was Active with the correct HSRP virtual IP while R1 remained unavailable.

R2 was Active with the corrected virtual IP 10.10.10.1.

Post-Remediation

R2 — show running-config interface

show running-config interface GigabitEthernet0/0

Used to verify the corrected HSRP configuration after remediation.

HSRP Investigation Result

CLI evidence established that R1 was configured as the intended Active gateway with virtual IP 10.10.10.1, while R2 was initially configured with the incorrect virtual IP 10.10.10.11. After R1 failed, R2 transitioned to Active but could not provide the client's expected gateway. Correcting R2's virtual IP to 10.10.10.1 allowed R2 to provide the expected gateway and restore client connectivity.

INC-007 — NAT / PAT CLI Evidence

Cisco IOS CLI was used to isolate a NAT translation failure by verifying interface roles, routing, NAT configuration, the NAT source ACL, translation state, and post-remediation translation activity.

Interface Verification

show ip interface brief

show ip interface brief

Used to verify interface status and addressing before investigating the NAT configuration.

NAT Inside

show running-config interface g0/0

show running-config interface GigabitEthernet0/0

Used to verify that the client-facing interface was configured as the NAT inside interface.

NAT Outside

show running-config interface g0/2

show running-config interface GigabitEthernet0/2

Used to verify that the ISP-facing interface was configured as the NAT outside interface.

Routing

show ip route

show ip route

Used to verify routing information and separate a routing failure from the NAT translation failure.

NAT Configuration

show running-config | section nat

show running-config | section nat

Used to verify NAT inside/outside roles and the PAT overload statement applied to the ISP-facing interface.

NAT ACL

show running-config | section access-list

show running-config | section access-list

Used to inspect the source ACL referenced by the NAT overload configuration.

Troubleshooting

show access-lists NAT-INSIDE

show access-lists NAT-INSIDE

Used to inspect the NAT source ACL and identify that the configured permit statement referenced the wrong network.

The ACL permitted 10.10.20.0/30 even though the affected client LAN was 10.10.10.0/24.

NAT State

show ip nat translations

show ip nat translations

Used to determine whether the affected client traffic was creating NAT translation entries.

No translation entry was present during the failed connectivity test.

NAT Statistics

show ip nat statistics

show ip nat statistics

Used to inspect NAT operation and determine whether translations were being created.

NAT Debug

debug ip nat

debug ip nat

Used after remediation to observe NAT processing and provide additional evidence that translation was occurring.

Post-Remediation

show access-lists NAT-INSIDE

show access-lists NAT-INSIDE

Used to verify that the corrected ACL matched the actual client LAN after remediation.

The corrected 10.10.10.0/24 entry recorded three matches, confirming that client traffic was now selecting the NAT policy.

Post-Remediation

show ip nat translations

show ip nat translations

Used to verify that active NAT translations were created after correcting the source ACL.

Post-Remediation

show ip nat statistics

show ip nat statistics

Used to confirm NAT translation activity after the configuration correction.

CLI Investigation Summary

The CLI investigation progressed from interface and routing verification into NAT-specific inspection. The NAT overload statement and inside/outside interface roles were confirmed, while the NAT-INSIDE ACL was found permitting the wrong source network. The empty translation table provided additional evidence of the failure.

After correcting the ACL to permit 10.10.10.0/24, the ACL recorded matching traffic and NAT translations populated. NAT statistics and debug output provided additional post-remediation verification.

CLI evidence established that the BGP session itself was operational. The failure was isolated to the configured network advertisement. R1 originally referenced 10.10.100.0/24 instead of 10.10.10.0/24. After correcting the network statement, the affected prefix appeared in the BGP table, was advertised to the ISP, and end-to-end connectivity was restored.

Investigation Workflow

01 — Observe

Identify the symptom and affected service.

02 — Hypothesize

Develop possible causes based on the symptoms.

03 — Verify

Select CLI commands that can confirm or eliminate each hypothesis.

04 — Remediate

Correct the identified configuration or network issue.

05 — Validate

Use CLI and packet evidence to confirm the fix.
